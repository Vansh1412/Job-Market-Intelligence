## 1. Executive Summary & Identity Policy

Under the JOBINTEL 2.0 Corporate Identity Governance Specification:
1. **Statutory Primacy:** Corporate entities are identified and anchored exclusively by sovereign government registries, never by marketing brand names, web scrapers, or third-party aggregators.
2. **Anti-Collapsing Enforcement:** Operating entities, parents, and subsidiaries maintain distinct legal personhood. A brand parent is never collapsed into an operating subsidiary, nor is a subsidiary merged into a holding company without certified cross-market evidence.
3. **Headcount Governance:** Headcount stock (total global or domestic workforce) must never be conflated with flow metrics (job vacancy postings). Headcount bands are reported from audited statutory disclosures, preserving exact band semantics.

**Forensic Finding:**  
Both identifiers share the immutable jurisdictional incorporation sequence:
- State: `KA` (Karnataka)
- Year: `1981`
- Entity Type: `PLC` (Public Limited Company)
- Sequence: `013115`

The authoritative canonical registration number recognized by the MCA API, the candidate register, and the staging frontend (`frontend/src/pages/EmployersPage.tsx`) is **`L85110KA1981PLC013115`**. The ingestion engine and tests strictly adopt `L85110KA1981PLC013115`.

### 3.2 Nuance 2: Arm Limited Sovereign Market Code Mapping

Under ISO-3166-1 alpha-2, the United Kingdom is assigned code `GB`. However, the JOBINTEL 2.0 Global Foundation architecture canonically defines the sovereign market enum as `MarketId.UK = "UK"` (`src/backend/schemas/market.py`).

In `src/backend/employers/resolver.py` line 247:
```python
emp_market = emp.headquarters_country.upper().strip()
# ...
cand_market = request.market_id.upper().strip() if request.market_id else None
# ...
if cand_market and cand_market != emp_market:
    # Cross-jurisdiction identifier match requires manual review
    stat_match = False
```

If `comp_uk_arm` were assigned `headquarters_country="GB"`, any statutory query passed with `market_id="UK"` would trigger `cand_market != emp_market` (`"UK" != "GB"`), erroneously degrading an exact statutory match to `AMBIGUOUS_CANDIDATE`.

Because `EmployerProfile.headquarters_country` regex is `^[A-Z]{2}$`, setting `headquarters_country="UK"` perfectly satisfies the schema constraint, aligns with `MarketId.UK`, and enables deterministic `EXACT_IDENTIFIER_MATCH` and `AUTOMATICALLY_RESOLVED` verification.
