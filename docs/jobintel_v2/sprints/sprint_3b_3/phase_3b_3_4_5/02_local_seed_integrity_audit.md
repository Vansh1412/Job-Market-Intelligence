## 2. Cryptographic Fingerprint & Line-Ending Forensic Resolution

### 2.1 The Hash Discrepancy Phenomenon

Sprint 3B.3.3.4.4 reported the seed SHA-256 digest as:
`0509508464e1e3fb86456e333fb1be38c99fe3d63e040db04d942832ef84d3a5`

However, a raw binary SHA-256 read of either file on disk yields:
`470269f226fc10b2cae678933ef5eaed5c23f8691862f861ae556d04e9804ed9`

### 2.2 Forensic Reproduction & Explanation

In `src/backend/ingestion/employers_pilot.py`:
```python
def serialize_profiles(profiles: Sequence[EmployerProfile]) -> str:
    raw = [p.model_dump(mode="json") for p in profiles]
    return json.dumps(raw, indent=2, sort_keys=True)

def compute_manifest_sha256(content: str) -> str:
    return hashlib.sha256(content.encode("utf-8")).hexdigest()
```

- When Python generates `serialized` in memory, string line breaks are standard UNIX line feeds (`\n`).
- Computing `hashlib.sha256(content.encode("utf-8"))` over this in-memory string evaluates the LF representation, producing `0509508464e1e3fb86456e333fb1be38c99fe3d63e040db04d942832ef84d3a5`.
- When writing to disk on Windows without `newline=""` (`open(path, "w", encoding="utf-8")`), Python's runtime translates `\n` to Windows CRLF (`\r\n`).
- Reading the raw bytes (`open(path, "rb").read()`) includes the carriage returns, altering the cryptographic digest to `470269f226fc10b2cae678933ef5eaed5c23f8691862f861ae556d04e9804ed9`.

### 2.3 Cryptographic Digest Matrix

| Digest Type | Evaluation Input | SHA-256 Hex Digest | Match Status |
| :--- | :--- | :--- | :--- |
| **Normalized UNIX LF** | File text with `\r\n` converted to `\n` | `0509508464e1e3fb86456e333fb1be38c99fe3d63e040db04d942832ef84d3a5` | **EXACT MATCH TO CLAIM** |
| **Raw Windows CRLF** | File binary bytes on disk (`rb`) | `470269f226fc10b2cae678933ef5eaed5c23f8691862f861ae556d04e9804ed9` | **EXACT DISK MATCH** |
| **Canonical JSON RFC 8785** | Minified, sorted keys, no whitespace separators `(',', ':')` | `1c82f5b9c36a854b6053a04813f3e52f9c248f584380bf21a76d8bd23d30c9dd` | **DETERMINISTIC JCS** |

> [!NOTE]
> The reported hash `0509508464...` was not fabricated; it represents the in-memory UNIX LF string generated by the ingestion script before Windows CRLF file serialization. In future pipelines, file writing should enforce `newline="\n"` to guarantee platform-independent binary digests.

### 3.2 Schema Architecture Limitation: The Missing Governance Fields

A major architectural finding of this audit is that **the Pydantic schema `EmployerProfile` does not contain fields for statutory governance or headcount metrics**:
- ❌ No `statutory_id`
- ❌ No `statutory_authority`
- ❌ No `headcount` or `headcount_governance_basis`
- ❌ No `source_license`

In `src/backend/ingestion/employers_pilot.py`, `PILOT_COHORT_SPECS` defines these attributes:
```python
"statutory_authority": "ASIC",
"statutory_id": "53102443916",
"headcount_governance_basis": "WGEA Size Band (1,000 to 4,999)",
"source_license": "CC-BY 4.0 (Australian Government)",
```
However, when `build_candidate_profiles()` constructs the `EmployerProfile` models, these fields are **silently omitted** because `EmployerProfile` has no such attributes defined!

#### How Entity Resolution Actually Works Under This Limitation
Instead of reading a direct `statutory_id` field, `src/backend/employers/resolver.py` parses statutory identifiers dynamically from the URL or text in `source_references[].source_reference`:
- For Atlassian: `https://abr.business.gov.au/ABN/View?id=53102443916` -> regex extracts ABN `53102443916`.
- For Microsoft: `https://www.sec.gov/edgar/browse/?CIK=0000789019` -> regex extracts CIK `0000789019`.
- For Arm: `https://find-and-update.company-information.service.gov.uk/company/02557590` -> regex extracts CRN `02557590`.
- For DBS: `https://www.tis.bizfile.gov.sg/uen/196800306E` -> regex extracts UEN `196800306E`.
- For Infosys: `https://www.mca.gov.in/mcafoportal/companyLLPMasterData.do?cin=L85110KA1981PLC013115` -> regex extracts CIN `L85110KA1981PLC013115`.

> [!WARNING]
> Relying on regular expressions over source reference URLs rather than explicit, validated statutory identifier fields creates runtime fragility. If a source URL format changes or uses an alternative route, entity resolution fails silently.

### 3.3 Infosys Canonical CIN Resolution
Historical draft project records referenced CIN `L72200KA1981PLC013115` based on the 2004 National Industrial Classification (NIC) software activity code `72200`. MCA master data records and SEBI filings confirm the canonical legal CIN is **`L85110KA1981PLC013115`**. The seed file correctly uses `L85110KA1981PLC013115`.

### 3.4 Arm Limited Sovereign Market Alignment
ISO 3166-1 alpha-2 assigns the country code `GB` to the United Kingdom. However, JOBINTEL 2.0 defines `MarketId.UK = "UK"`. In `EmployerProfile`, `headquarters_country` requires regex `^[A-Z]{2}$`. Setting `headquarters_country="UK"` aligns with `MarketId.UK` and prevents cross-market conflict flags in `resolver.py`.

### 3.5 Headcount Metrics: Exact Counts vs. Regulatory Size Bands
- **Atlassian:** 1,000 to 4,999 employees (WGEA reporting size band). Under Australian Workplace Gender Equality Agency rules, employers in this tier report size bands rather than exact headcounts.
- **Arm Limited:** 1,000 to 4,999 employees (UK Gender Pay Gap reporting band). Companies House and GPG disclose banded employer workforce sizes.
- **Microsoft:** 228,000 employees. U.S. SEC Form 10-K discloses consolidated global full-time employees (approx. 125,000 domestic US, 103,000 international).
- **DBS Bank:** 36,000 employees. Group annual report operating headcount.
- **Infosys:** 317,240 employees. SEBI Business Responsibility and Sustainability Report (BRSR) audited consolidated workforce.
