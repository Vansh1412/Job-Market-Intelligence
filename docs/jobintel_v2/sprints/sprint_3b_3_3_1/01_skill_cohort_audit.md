# SPRINT 3B.3.3.1: SKILL COHORT SAMPLE SIZE AUDIT
## Critical Forensic Investigation: Lineage, Semantics & Denominator Discrepancy

**Sprint ID:** 3B.3.3.1  
**Audit Target:** Skill demand prevalence and sample size disclosure (`frontend/src/pages/SkillsPage.tsx`)  
**Displayed Values Under Investigation:**  
- **USA:** `Cohort N = 34,036`  
- **India:** `Cohort N = 5,859`  
**Auditor:** Independent Principal Engineer & Statistical Auditor  
**Audit Date:** 2026-11-17  
**Finding Verdict:** **CRITICAL SEMANTIC DEFECT (INCORRECT DENOMINATOR)**

---

## 1. Executive Summary

During Sprint 3B.3.3, a change was introduced in `frontend/src/pages/SkillsPage.tsx` to surface sample size disclosures on skill demand metrics:
```tsx
<span style={{ fontSize: '0.72rem', color: '#64748B' }}>
  {detailPostings.toLocaleString()} postings (Cohort N = {isUSA ? '34,036' : '5,859'})
</span>
```

This forensic audit traced the end-to-end data lineage of these values from raw data files, through feature extraction, backend services, API routers, and UI presentation.

**Critical Finding:**  
The values `34,036` (USA) and `5,859` (India) are **SUPERVISED SALARY MODELING TRAINING SIZES**, NOT the job-posting observation population used for skill demand frequency!
Specifically, in the USA market, Python displays:
- Posting Count: **31,676 postings**
- Demand Prevalence: **9.4%**
- Displayed Cohort: **`Cohort N = 34,036`**

If $N = 34,036$ were the true denominator, $31,676 / 34,036 = 93.1\%$, completely contradicting the displayed 9.4% prevalence! In reality, 31,676 postings and 9.4% prevalence were calculated over the **335,995 deduplicated job posting corpus**. Displaying `Cohort N = 34,036` is statistically invalid, misleading to users, and constitutes a critical semantic error.

## 2. Nine-Point Data Lineage Trace

### 2.1 Backend Data Source
- **USA:** `reports/tables/phase3/skill_frequency.csv`, generated by `src/run_phase3_eda.py` from `data/processed/modeling_dataset.parquet` and `data/processed/skill_matrix_technical.parquet`.
- **India:** `reports/tables/india/india_skill_analytics.json`, generated by `src/india/cohort.py` and `src/india/archetypes.py` from `data/processed/india/india_modeling_cohort.parquet`.

### 2.2 Dataset and Posting Cohort Definitions
- **USA Supervised Modeling Cohort ($N = 34,036$):** A heavily filtered subset of tech postings that explicitly disclosed annual USD base salaries between \$30,000 and \$600,000.
- **USA Full Deduplicated Corpus ($N = 335,995$):** The complete corpus of deduplicated job postings from which general tech skill frequencies were extracted.
- **India Supervised Modeling Cohort ($N = 5,859$):** Postings with explicit CTC compensation across 6 major Indian tech hubs.
- **India Total Ingested Pool ($N = 97,318$):** The broader Indian job market posting collection.

### 2.3 Filtering Rules
- **USA ($34,036$):** Raw ATS Ingestion ($394,300$) $\rightarrow$ Casing Deduplication ($335,995$) $\rightarrow$ Verified Tech Postings ($114,873$) $\rightarrow$ Salary Disclosed USD ($34,121$) $\rightarrow$ Trimmed Outliers (\$30k–\$600k) ($34,036$).
- **India ($5,859$):** Raw Ingested ($97,318$) $\rightarrow$ Deduplicated & Filtered for Valid Tier-1/Tier-2 Tech Roles with Explicit Salary & Experience Fields ($5,859$).

### 2.4 Time Period
- **USA:** 2023–2024 Tech Requisitions.
- **India:** 2024–2025 Indian Tech Postings.

### 2.5 Market
- **USA:** Metropolitan technology markets (San Francisco, New York, Seattle, Austin, etc.).
- **India:** Tier-1 and Tier-2 technology hubs (Bengaluru, Hyderabad, Pune, Mumbai, NCR, Chennai).

### 2.6 Deduplication Logic
- Multi-field hashing on normalized company name, job title, and sanitized job description body.

### 2.7 Skill Extraction Population
- **USA:** In `src/run_phase3_eda.py`, skill prevalence was computed on BOTH populations and recorded in `skill_frequency.csv`:
  - `Corpus_Count` and `Corpus_Prevalence`: Computed across $N = 335,995$ postings.
    - Example (Python): `Corpus_Count = 31,676`, `Corpus_Prevalence = 0.094275` ($9.43\%$).
  - `Modeling_Count` and `Modeling_Prevalence`: Computed across $N = 34,036$ postings.
    - Example (Python): `Modeling_Count = 11,593`, `Modeling_Prevalence = 0.340610` ($34.06\%$).
- **India:** In `src/india/cohort.py`, skill prevalence was computed over the subset of postings with extracted technical skills (~$5,316$ postings with non-empty skills out of $5,859$).

### 2.8 API Response
- In `src/backend/routers/skills.py` (`GET /skills/detail/{skill_name}`):
  ```python
  if "Corpus_Count" in row_freq.columns:
      postings = int(row_freq["Corpus_Count"].values[0])  # 31,676
  if "Corpus_Prevalence" in row_freq.columns:
      prev = float(row_freq["Corpus_Prevalence"].values[0]) * 100  # 9.43%
  ```
  The backend API explicitly returns the **Corpus** count ($31,676$) and **Corpus** percentage ($9.43\%$). It does NOT return any cohort denominator field in the response payload.
- In `src/backend/routers/india.py` (`GET /india/skills/{skill_name}`):
  Returns `posting_count: 723` and `demand_percentage: 13.6%`. It does NOT return a cohort denominator field.

### 2.9 Frontend Display
- `frontend/src/pages/SkillsPage.tsx` takes `detailPostings` ($31,676$) and hardcodes:
  `{detailPostings.toLocaleString()} postings (Cohort N = {isUSA ? '34,036' : '5,859'})`
- This renders on screen as:
  **"31,676 postings (Cohort N = 34,036)"** next to **"9.4%"**.

## 3. Findings Matrix

### Finding SKL-01: Severe Denominator Conflation in Skills UI
- **Claim:** The displayed `Cohort N = 34,036` represents the job posting population from which the 31,676 Python postings were observed.
- **Actual Implementation:** $34,036$ is the supervised salary modeling dataset size. The $31,676$ postings count was derived from the $N = 335,995$ general corpus.
- **Evidence:**
  - `reports/tables/phase3/skill_frequency.csv`: Line 2: `python,11593,0.3406099,31676,0.0942752,1.07693`.
  - Python in the modeling cohort appeared in $11,593$ postings ($34.06\%$).
  - Python in the general corpus appeared in $31,676$ postings ($9.43\%$).
  - Frontend displays $31,676$ with prevalence $9.4\%$ while claiming $N = 34,036$.
- **Verification Method:** Source code inspection, data service inspection, and CSV artifact verification.
- **Risk:** **CRITICAL**. Undermines platform credibility. Users and auditors can immediately observe that $31,676 / 34,036 = 93.1\%$, creating a visible mathematical contradiction against the $9.4\%$ metric badge.
- **Required Action:**
  - In a corrective sprint, update the backend API to return explicit population metadata:
    `{ "postings": 31676, "prevalence_pct": 9.4, "population_size": 335995, "population_name": "Full Analyzed Corpus" }`.
  - Remove the hardcoded `(Cohort N = 34,036)` in `SkillsPage.tsx` and render either `Corpus N = 335,995` or switch both count and prevalence to the modeling cohort ($11,593$ postings / $34.06\%$ prevalence across $N = 34,036$).
- **Status:** **`INCORRECT`**

### Finding SKL-02: India Skill Denominator Imprecision
- **Claim:** The India skill detail displays postings count out of a cohort of $N = 5,859$.
- **Actual Implementation:** Top skills in India show counts such as $723$ postings with $13.6\%$ prevalence ($723 / 0.136 \approx 5,316$). The active skill-bearing denominator was $5,316$, not the full $5,859$ rows (which include skill-sparse postings).
- **Evidence:** `reports/tables/india/india_skill_analytics.json` inspection.
- **Verification Method:** Statistical quotient recalculation.
- **Risk:** Minor mathematical discrepancy ($5,316$ vs $5,859$), but contributes to denominator ambiguity.
- **Required Action:** Expose exact active denominator `population_n` from `india_skill_analytics.json` in the API.
- **Status:** **`VERIFIED WITH LIMITATIONS`**

---

## 4. Conclusion & Directive

The skill cohort sample size display introduced in Sprint 3B.3.3 contains a critical semantic error. It must NOT be silently patched during this read-only audit. It must be formally logged as a blocking defect requiring a dedicated corrective sprint prior to staging release.
