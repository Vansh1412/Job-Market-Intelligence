  Prediction using Machine Learning

One-line pitch:
  Extract skills from job postings, discover job archetypes with PCA +

  RQ1. Which skills and skill combinations are most associated with higher
       salaries?
  RQ2. Do job postings naturally form skill-based archetypes?
  RQ3. Does salary-prediction error differ across archetypes?
       (This drives the bias-variance and error-analysis section.)

3. PROBLEM DEFINITION
------------------------------------------------------------------------------
Primary task (regression):
  Predict annual salary (normalized to one currency and period, e.g. INR LPA
  or USD/year) from job role, experience, location, and skills.

Secondary task (classification, optional but recommended):
  Classify the job into a category (e.g. Data Scientist, Backend Developer,
  DevOps, Data Analyst, ML Engineer) OR into salary bands (Low / Medium /
  High). This lets you report Accuracy, Precision, Recall, F1, AUC,
  Log Loss and Confusion Matrix as the brief lists.

Unsupervised task:
  Cluster postings in skill space to find job archetypes.

5. DATA PREPROCESSING PLAN
------------------------------------------------------------------------------
5.1 Cleaning
  - Remove exact duplicates (same title + company + description).
  - Standardize column names; fix dtypes.
  - Parse salary strings; convert ranges to midpoint; unify currency and
    period (monthly -> annual); document every assumption.
  - Drop rows with missing salary for supervised tasks (report how many).

5.2 Missing values
  - Categorical: fill with "Unknown" or mode (justify choice).
  - Numeric (experience): median imputation.
  - Report missing-value table before and after.

5.3 Outliers
  - Inspect salary with boxplot and IQR rule.
  - Prefer log-transform of salary over deleting outliers; compare both.

5.4 Categorical encoding
  - Low-cardinality (experience level, work mode): one-hot encoding.
  - High-cardinality (location, company): top-N + "Other", or target/
    frequency encoding.
  - Job title: group into role families (map titles to ~8-12 categories).

5.5 Skill extraction (the key feature step)
  - Build a skill vocabulary (e.g. python, sql, aws, docker, kubernetes,
    spark, tableau, power bi, tensorflow, pytorch, java, react, git ...).
  - Method A: keyword matching against the vocabulary -> multi-hot matrix.
  - Method B: TF-IDF on description text (limit max_features ~ 300-500).
  - Use Method A as primary (interpretable), Method B as comparison.

5.6 Feature scaling
  - StandardScaler for numeric features and before PCA / MLP.
  - Tree models do not need scaling, but keep one shared pipeline for
    fairness.

5.7 Data splitting
  - 80/20 train/test split with fixed random_state.
  - Use stratification for classification.
  - Fit scalers/encoders/PCA on TRAIN ONLY (avoid data leakage; mention this
    explicitly in the report).
  - Use 5-fold cross-validation on train for model selection.

7. DIMENSIONALITY REDUCTION AND CLUSTERING (UNSUPERVISED)
------------------------------------------------------------------------------
7.1 PCA
  - Apply on scaled skill matrix.
  - Plot scree plot + cumulative explained variance.
  - Choose components covering ~80-90% variance; also keep a 2D projection
    for visualization.
  - Inspect loadings: which skills define PC1, PC2? (e.g. PC1 = "data/ML
    stack", PC2 = "web/backend stack").

7.2 K-Means
  - Try k = 2..10.
  - Select k using Elbow (inertia) + Silhouette score (+ Davies-Bouldin).
  - Fit final k; plot clusters on PCA 2D.
  - Profile each cluster: top skills, median salary, common roles, size.
  - Name the archetypes (e.g. "ML/AI Engineers", "Data Analysts / BI",
    "Backend + Cloud", "DevOps/Platform", "Frontend/Full-stack").

7.3 Optional: Hierarchical clustering
  - Dendrogram on a sample (e.g. 500-1000 rows) as comparison to K-Means.

7.4 Use clusters downstream
  - Add cluster label as a feature (compare models with vs without it).
  - Use clusters later for per-archetype error analysis (RQ3).

8. SUPERVISED MODELING PLAN
------------------------------------------------------------------------------
8.1 Baseline
  - DummyRegressor (predict mean/median) - sets the floor for R2.

8.2 Models (regression target: log salary or salary)
  M1  Linear Regression / Ridge / Lasso   (interpretable baseline)
  M2  Random Forest Regressor             (ensemble, bagging)
  M3  Gradient Boosting (or XGBoost)      (ensemble, boosting)
  M4  MLP Regressor (feedforward NN)      (neural comparison)

8.3 Feature-set experiments (this makes the comparison meaningful)
  Set A: original features (encoded + skills multi-hot)
  Set B: PCA-reduced features
  Set C: Set A + cluster label
  -> Compare each model across Sets A/B/C in a results table.

8.4 Hyperparameter tuning
  - GridSearchCV / RandomizedSearchCV with 5-fold CV.
  - Suggested grids:
      Ridge: alpha in [0.01, 0.1, 1, 10, 100]
      RF: n_estimators [100, 300], max_depth [None, 10, 20],
          min_samples_leaf [1, 3, 5]
      GB: n_estimators [100, 300], learning_rate [0.03, 0.1],
          max_depth [3, 5]
      MLP: hidden_layer_sizes [(64,), (128,64)], alpha [1e-4, 1e-2],
           early_stopping=True
  - Report best params and CV score.

8.5 Optional classification track
  - Target: salary band (tertiles) or role family.
  - Models: Logistic Regression, Random Forest, Gradient Boosting.
  - Metrics: Accuracy, Precision, Recall, F1 (macro), ROC-AUC (OvR),
    Log Loss, Confusion Matrix.

16. RISKS AND MITIGATIONS
------------------------------------------------------------------------------
  Risk: Salary missing or inconsistent across rows
    -> Choose a dataset with high salary coverage; normalize early; fall
       back to salary bands.
  Risk: Skill extraction misses synonyms (e.g. "pytorch" vs "torch")
    -> Maintain an alias dictionary; manually inspect a sample of 50 rows.
  Risk: Data leakage (fitting PCA/scaler on all data)
    -> Use sklearn Pipelines; fit on train only.
  Risk: Overfitting with many sparse features
    -> Regularization, CV, feature-count limits, compare with PCA set.
  Risk: Scope creep (dashboard eating report time)
    -> Treat the demo as optional; the report and analysis carry the marks.
  Risk: Class/segment imbalance across archetypes
    -> Report per-cluster sample sizes alongside per-cluster errors.
